# Hello source example

Use this source-checkout example to see the smallest complete source workflow:
declare a tree, compute current status on read, serve it through Source API, and
browse it under `/repo` with the ActiveFS CLI.

For a new npm project, follow [Build a source server](../../docs/guides/build-a-source-server.md)
instead. For the installed-CLI demo, use the [quickstart](../../docs/quickstart.md).

## Explore the tree once

From the repository root:

```console
$ pnpm --filter @activefs/example-hello-source build
$ node examples/hello-source/dist/index.js --once

hello-source entries: /README.txt, /bin, /data, /notes
hello-source read: Hello from an ActiveFS Source API tree.
hello-source matches: /notes/source-api.txt:1
```

The one-shot command lists the tree, reads generated content, and searches it,
then exits. Use the server workflow below to connect the CLI and repeat reads of
a status file whose timestamp is computed on demand.

## Start the source

Keep this process running in the first terminal:

```console
$ PORT=3999 node examples/hello-source/dist/index.js

ActiveFS hello source listening at http://127.0.0.1:3999/_activefs/
Try: activefs remote add repo http://127.0.0.1:3999/_activefs/
```

On Windows PowerShell, start it with:

```powershell
$env:PORT = "3999"
node examples/hello-source/dist/index.js
```

The helper chooses `/_activefs/` as its discovery route. Source API does not
require applications to use that path.

## Connect it

Open another terminal at the repository root. Put the workspace CLI on your
`PATH`, then add the source as the `repo` remote:

```console
$ export PATH="$PWD/node_modules/.bin:$PATH"
$ activefs remote add repo http://127.0.0.1:3999/_activefs/

Configured remote repo /repo -> http://127.0.0.1:3999/_activefs/
```

On Windows PowerShell, put the workspace CLI on `PATH` and add the same
remote with:

```powershell
$env:Path = "$PWD\node_modules\.bin;$env:Path"
activefs remote add repo http://127.0.0.1:3999/_activefs/
```

## Read the tree

List the root:

```console
$ activefs list /repo

directory /repo/bin
directory /repo/data
directory /repo/notes
file      /repo/README.txt
```

Read the computed status:

```console
$ activefs read /repo/data/status.json

{
  "schemaVersion": 1,
  "source": "hello-source",
  "status": "ready",
  "checkedAt": "2026-07-21T12:00:00.000Z"
}
```

Your timestamp will differ. Read the file again and `checkedAt` changes because
the `json(() => ...)` callback runs for each read.

Read and search the other generated content:

```console
$ activefs read /repo/README.txt

Hello from an ActiveFS Source API tree.

$ activefs grep generated /repo

# activefs grep: scan
/repo/notes/source-api.txt:1:14:This file is generated by examples/hello-source.
```

## Paths

| Path | Result |
|---|---|
| `/README.txt` | Small text file for the first read. |
| `/data/status.json` | JSON computed from current source state on every read. |
| `/notes/source-api.txt` | Generated text used by the search example. |
| `/notes/change-me.txt` | Points to the source file to edit. |
| `/bin/sample.bin` | Small binary file. |

## Change the source

Edit `examples/hello-source/src/index.ts`, rebuild, and restart the server. Read
the changed file through ActiveFS again. The running source remains
authoritative for its data.

## Clean up

Remove the configured remote:

```bash
activefs remote remove repo
```

Then press `Ctrl-C` in the source-server terminal.

## Limits

This example is read-only and credential-free. It does not cover persistent
provider storage, authorization, writes, multi-remote composition, or an
OS-visible mounted folder.
